Web 弱點掃描工具實務教學 (純網頁 Codespaces 版)

本平臺採用完全免安裝、純瀏覽器執行的 GitHub Codespaces 雲端架構，讓學生與測試人員能直接透過網頁體驗 OWASP ZAP、Burp Suite 與 Juice Shop 的滲透測試實務。

1. 工具介紹與比較

在資安稽核中，中間人代理 (Proxy) 能攔截與動態修改 HTTP/HTTPS 封包。以下為兩種常見代理工具的特性比較：

比較項目 OWASP ZAP Burp Suite Community
授權費用 完全免費 / 開源 免費社區版 / 專業版需付費
Codespaces 雲端相容性 極佳 (支援免密碼 Daemon 模式) 極佳 (支援 KasmVNC 網頁雲端桌面)
自動化掃描能力 完整支援 CLI 引擎與基線掃描 (`zap-baseline`) 社區版無自動化主動掃描功能
手動改包與重發 (Repeater) 支援 API 與簡易攔截 強大且直觀（資安社群產業標準）

2. 核心原理與漏洞解析

中間人代理 (MitM Proxy)

代理伺服器位於用戶端與 Web 伺服器之間。所有發出的 HTTP 請求都會先經過 Proxy 監聽、暫停與修改後再發送至目標網站。

SQL 注入 (SQL Injection) 漏洞

當應用程式未對使用者輸入進行驗證，直接拼接到資料庫查詢語句時，攻擊者可輸入如 ' OR 1=1 -- 來破壞原始 SQL 邏輯並繞過登入驗證。

3. Codespaces 雲端實作建置指南

🚀 免安裝！使用 GitHub Codespaces 執行雲端靶場與網頁版 Burp Suite：
完全無須在個人電腦安裝 Docker、Burp Suite 或任何軟體，直接在瀏覽器視窗中啟動完整實作環境！

快速啟動 3 步驟：

  1. 在本 GitHub 專案頁面點擊 <> Code ➔ 切換至 Codespaces ➔ 點擊 Create codespace on main。
  2. 開啟雲端 VS Code 後，在下方 Terminal (終端機) 輸入以下 command 一鍵啟動 Juice Shop、ZAP API 與 KasmVNC 網頁桌面版 Burp Suite： 
    docker run -d -p 3000:3000 --name juiceshop bkimminich/juice-shop && docker run -d -p 8080:8080 --name zap -e ZAP_AUTH_HEADER_VALUE="" zaproxy/zap-stable zap.sh -daemon -host 0.0.0.0 -port 8080 -config api.addrs.addr.name=".*" -config api.addrs.addr.regex=true -config api.disablekey=true && docker run -d -p 6080:6080 --name burp -e VNC_PASSWORD=admin kasmweb/burpsuite:1.14.0
  3. 切換至 VS Code 下方的 Ports 頁籤：
    • Port 3000：右鍵選取 Open in Browser 開啟 Juice Shop 靶場網頁。
    • Port 8080：右鍵選取 Open in Browser 開啟 OWASP ZAP 免登入 API 主頁。
    • Port 6080：右鍵選取 Open in Browser 開啟 Burp Suite 雲端 VNC 桌面 (登入密碼為：admin)。

4. 6 大實作演練任務

演練一：SQL 注入（萬能密碼）繞過登入

  1. 開啟 Port 3000 的 Juice Shop 網頁，點擊右上角 「帳號」➔「登入」。
  2. 在 電子郵件 欄位輸入萬能密碼：' OR 1=1 --
  3. 在 密碼 欄位隨意輸入（如 123456）。
  4. 點擊 「登入」，驗證是否成功以最高管理員 (admin@juice-sh.op) 身份登入系統！

演練二：DOM-based XSS (跨站腳本攻擊) 注入

  1. 開啟 Juice Shop 網頁右上角的 搜尋欄位 (Search)。
  2. 複製並貼上 XSS 測試 Payload： 
    <iframe src="javascript:alert(`XSS`)">
  3. 按下 Enter 鍵搜尋，觀察瀏覽器是否彈出 XSS 提示視窗（證明 JavaScript 程式碼被成功注入並執行）。

演練三：敏感資料洩漏 (Sensitive Data Exposure) 探勘

  1. 在 Juice Shop 網址列後方加入 /ftp 路徑，例如： http://localhost:3000/ftp
  2. 檢視目錄列表中公開暴露的機密檔案。
  3. 嘗試點擊下載 acquisitions.md 或 coupons_2013.md.bak，觀察備份檔案與敏感商業資訊是否在未授權狀況下洩漏。

演練四：利用瀏覽器 DevTools 進行 API 請求分析與改包

  1. 在 Juice Shop 網頁按下 F12 開啟瀏覽器「開發者工具」，並切換至 Network (網路) 頁籤。
  2. 在網頁上隨意點擊商品發送評論，或切換商品頁面。
  3. 在 Network 頁籤中尋找回應為 JSON 格式的 REST API 請求（如 /rest/products/search 或 /api/Challenges）。
  4. 點擊檢視 Request/Response Header 與 Payload，觀察前端如何透過 API 與後端伺服器交換資料。

演練五：從 Codespaces 終端機發動 ZAP 自動化弱點掃描

  1. 回到 Codespaces 下方的 Terminal (終端機) 視窗。
  2. 複製並貼上以下 CLI 自動掃描指令，按下 Enter 執行： 
    docker run --net=host -t zaproxy/zap-stable zap-baseline.py -t http://localhost:3000
  3. 觀察 Terminal 中 ZAP 爬蟲與檢測進度，並於完成後檢視 PASS (通過)、WARN (警告) 與 FAIL (弱點) 的完整資安評估報告！

演練六：使用 Burp Suite (VNC 雲端桌面) 進行 HTTP 封包攔截與 Repeater 重放

  1. 開啟 Port 6080 網頁，連線至雲端 Linux 桌面（若需要密碼輸入 admin）。
  2. 點擊開啟桌面上的 Burp Suite Community Edition。
  3. 使用 Burp 內建的預設瀏覽器 (Burp Browser) 開啟 Juice Shop 靶場網址 (`http://localhost:3000`)。
  4. 切換至 Burp 的 Proxy ➔ Intercept 頁籤，點擊確認顯示 Intercept is on。
  5. 在 Juice Shop 網頁上嘗試輸入登入資訊，觀察 Burp Suite 成功攔截到的 POST 請求。
  6. 在攔截到的封包上點擊右鍵選擇 `Send to Repeater`（或按快捷鍵 Ctrl + R）。
  7. 切換至 Repeater 頁籤，修改請求內文參數（例如將電子郵件改為 ' OR 1=1 --）後點擊 Send，並於右方面板直接觀察伺服器回傳的 200 OK JSON 數據。

一、 測驗 5 題完整解答與詳細解析

第 1 題解答：選項 (2) 透過 Docker 啟動 Daemon 服務...

解析：OWASP ZAP 官方提供的 Daemon 模式可關閉 API key 驗證，使雲端虛擬機環境無需輸入帳密即可透過 Port 8080 進行溝通與控制。

第 2 題解答：選項 (2) SQL 注入攻擊...

解析：' OR 1=1 -- 利用單引號閉合語法、OR 1=1 恆真邏輯與 -- 註解符號，跳過密碼比對直接取得管理者權限。

第 3 題解答：選項 (1) 將後續 SQL 語法變成註解...

解析：在 SQL 語法中，-- 代表單行註解，資料庫會直接忽略其後的任何語句（包含原有的 AND password = '...'）。

第 4 題解答：選項 (2) Cross-Site Scripting (XSS)...

解析：XSS 漏洞允許攻擊者將 Script 注入網頁，當受害者開啟網頁時瀏覽器會執行該惡意程式，可能導致 Session Cookie 被竊取。

第 5 題解答：選項 (2) 使用者瀏覽器與目標伺服器之間...

解析：代理伺服器攔截並轉發雙向的 HTTP 請求與回應，讓測試人員能夠動態監聽或篡改傳輸封包內容。

二、 6 大實作演練 Writeup 與漏洞成因分析

演練 1：SQL 注入 (Admin Login)

成因：登入 API 使用未經過濾的字串拼接 SQL：SELECT * FROM Users WHERE email = 'USER_INPUT' AND password = '...';。當輸入 ' OR 1=1 -- 時，原語句變為 WHERE email = '' OR 1=1 --' ...，因 1=1 恆真且註解掉後續比對，資料庫回傳第 1 筆紀錄 (Admin)。

演練 2：DOM-based XSS

成因：前端框架 (Angular) 在處理 URL 搜尋參數時，使用了不安全的 HTML 渲染或未對 HTML 特殊字元 (如 <, >) 進行 HTML Entity 轉義，導致 <iframe> 被直接作為 DOM 節點解析並執行其中的 JavaScript。

演練 3：不安全的檔案目錄瀏覽 (Directory Listing)

成因：Web 伺服器對 /ftp 目錄未適當設定存取控制 (Access Control)，未關閉目錄瀏覽 (Directory Indexing)，且包含特權或備份檔案，導致敏感商業資訊直接暴露在網路上。

演練 4：API 分析與 Network 檢視

解析：現代 Single Page Application (SPA) 極度依賴 RESTful API 交換資料。資安測試人員可透過瀏覽器 DevTools 直接獲知 API Endpoint、HTTP Method (GET/POST/PUT) 與參數結構，以此尋找 IDOR 或權限提升等漏洞。

演練 5：ZAP Baseline 引擎運作原理

解析：zap-baseline.py 自動調用 ZAP Spider 爬蟲探索網站內部 URL，並套用被動掃描規則 (Passive Scan Rules) 檢測 HTTP Response Header (如 Lack of Anti-clickjacking Header, X-Content-Type-Options Missing 等)，迅速提供開箱即用的基本資安防禦指引。

演練 6：Burp Suite 封包攔截與 Repeater 手動滲透

解析：Burp Suite Proxy 的核心作用在於打破前端網頁的控制與限制（如 HTML5 validation、JavaScript 欄位長度限制）。透過 Repeater，測試人員可以獨立於瀏覽器之外，重複修改 HTTP Request 欄位並多次發送，以便探測後端 API 是否存在輸入驗證瑕疵或未處理的異常邏輯。
