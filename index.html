Web 弱點掃描工具實務教學

歡迎來到本課程！本平臺專為資安初學者與軟體開發人員設計，全面涵蓋 OWASP ZAP 與 Burp Suite 的基礎原理、環境建置、漏洞識別及自動化掃描演練。

1. 工具介紹與詳細比較

在網站安全稽核與滲透測試中，中間人代理 (Man-in-the-Middle Proxy) 是最核心的工具類別。其中，OWASP ZAP 與 Burp Suite 佔據了業界最主要的地位。

工具定位簡述

  • OWASP ZAP (Zed Attack Proxy)：由 OWASP 維護的開源旗艦專案，強調免費、完全無限制與高度自動化，極適合整合進 DevSecOps 與 CI/CD 流程中。
  • Burp Suite：由 PortSwigger 公司開發，為商業資安團隊與滲透測試人員的標準工具，提供極強的手動分析、重放與解碼模組。

2. 核心原理與漏洞解析

代理 (Proxy) 運作拓撲結構

代理工具充當瀏覽器（用戶端）與 Web 伺服器之間的中介。當瀏覽器發送 HTTP/HTTPS 請求時，封包會先被 Proxy 捕捉，允許測試人員進行檢查、暫停與篡改，隨後再轉發至目標伺服器。

圖 1：HTTP/HTTPS 中間人代理 (MitM Proxy) 的封包攔截與轉發流程

HTTPS 憑證解密 (SSL/TLS Interception)

加密網站使用 TLS 協定傳輸資料。為了使代理工具能看懂 HTTPS 裡面的明文內容，代理工具會在本地動態生成目標網站的「偽造 TLS 憑證」。

關鍵步驟：瀏覽器預設會阻斷不受信任的憑證。因此測試前，必須將工具生成的 Root CA 憑證（如 `OWASP ZAP Root CA` 或 `PortSwigger CA`）匯入並設定為「受信任的根憑證頒發機構」。

弱點掃描分類

  • 被動掃描 (Passive Scanning)：僅觀察並分析經過 Proxy 的 Request/Response，不主動發送額外封包。適用於檢測安全標頭缺失（如 CSP, X-Content-Type-Options）或未帶有 `HttpOnly` / `Secure` 旗標的 Cookie。對目標系統零影響。
  • 主動掃描 (Active Scanning)：針對 URL 參數、Header、Body 參數等注入各種 Payload，透過觀察伺服器回覆以驗證潛在漏洞（如 SQLi、XSS）。會對目標伺服器產生較多流量與存取紀錄。

常見 Web 弱點大解密 (OWASP Top 10)

  1. SQL 注入 (SQL Injection)：應用程式未對使用者輸入進行過濾，直接拼接到資料庫查詢語句中，攻擊者可藉此讀取、修改資料庫內容。
  2. 跨站腳本攻擊 (Cross-Site Scripting, XSS)：攻擊者將惡意 JavaScript 腳本注入到網頁中，當其他使用者瀏覽該頁面時腳本會執行，導致 Session Cookie 被竊取。
  3. 不安全的直接物件引用 (IDOR)：系統僅依賴 URL 中的 ID 參數（如 `/user/profile?id=102`）來存取資源，而未嚴格驗證當前登入者是否有權限讀取該 ID 的資料。
  4. 跨站請求偽造 (CSRF)：利用使用者已登入的 Session 狀態，誘騙其點擊惡意連結，以使用者身分發送未授權的請求。

3. 完整步驟與實作演練

本章節以常見的 Web 安全練習靶場 OWASP Juice Shop 為例進行示範。

靶場環境準備：
您可以選擇開啟 OWASP Juice Shop 線上示範站，或在本地電腦執行 Docker 指令：
docker run -d -p 3000:3000 bkimminich/juice-shop (啟動後開啟 http://localhost:3000)

步驟一：瀏覽器與代理工具設定

  1. 開啟 Burp Suite 或 ZAP，確認代理監聽於 `127.0.0.1:8080`。
  2. 使用代理套件（如 SwitchyOmega）或開啟 Burp 內建瀏覽器 (Open Browser)。
  3. 前往 `http://http://127.0.0.1:8080` (ZAP) 或 `http://burp` (Burp)，下載 CA 根憑證並安裝至瀏覽器信任區。

步驟二：手動封包篡改 (Burp Repeater 演練)

  1. 在 Juice Shop 登入頁面輸入測試帳號 `test@test.com` 與密碼 `123456`。
  2. 開啟 Burp Suite 的 Proxy -> Intercept is on。
  3. 點擊登入，此時 HTTP Request 會停留在 Burp 視窗中。
  4. 按下 Ctrl + R 將封包送至 Repeater 模組。
  5. 切換至 Repeater 頁籤，將 JSON 中的 `email` 修改為 ' OR 1=1 --，點擊 Send。
  6. 觀察右側 Response，成功獲得 HTTP 200 並返回管理者 JWT Token！

步驟三：自動化弱點掃描 (OWASP ZAP 演練)

  1. 開啟 OWASP ZAP，於主畫面點選 Quick Start -> Automated Scan。
  2. 輸入目標 URL：`http://localhost:3000`。
  3. 點擊 Attack 按鈕。
  4. ZAP 會自動發動 Spider (傳統爬蟲) 與 AJAX Spider 解析網站目錄。
  5. 爬蟲結束後，自動開啟 Active Scan 開始對每個端點進行弱點測試。
  6. 切換至底部 Alerts 頁籤，即可檢視評定為 High/Medium/Low 的漏洞報告。

一、 測驗題目解答與詳細解析

第 1 題解答：選項 (2) 解密 TLS 加密流量...

觀念解析：HTTPS 採用端到端加密。Proxy 為了讀取內容會動態簽發偽造憑證，若瀏覽器未信任 Proxy 的 Root CA，連線將被視為潛在攻擊並阻斷。

第 2 題解答：選項 (2) OWASP ZAP 為免費開源軟體...

觀念解析：OWASP ZAP 為完全免費且開源的工具；Burp Suite 社區版免費但移除了一鍵主動弱掃功能且爆破有速率限制。

第 3 題解答：選項 (2) 只分析現有流量而不發送額外請求...

觀念解析：被動掃描只監聽經過 Proxy 的 Header 與 Response（如檢測 Cookie 旗標、HTTP 安全標頭），不會主動觸發安全警報或影響系統運行。

第 4 題解答：選項 (2) SQL 注入 (SQL Injection)

觀念解析：利用單引號 `'` 閉合原查詢，並加上 `OR 1=1` 強制條件恆真，最後用 `--` 註解掉密碼比對邏輯。

第 5 題解答：選項 (1) 不安全的直接物件引用 (IDOR)

觀念解析：IDOR 發生於系統依賴使用者可控的輸入直接存取內部物件，但缺乏水平存取控制 (Horizontal Access Control) 驗證。

二、 Juice Shop 實作解答 (Writeup)

1. 管理員 SQL 注入驗證繞過

POST /rest/user/login HTTP/1.1
Content-Type: application/json

{
  "email": "' OR 1=1 --",
  "password": "anything"
}

說明：透過傳入 `' OR 1=1 --`，後端查詢語句變成 `SELECT * FROM Users WHERE email = '' OR 1=1 --' AND password = '...'`，直接返回第一個 User（通常為 Admin）。
