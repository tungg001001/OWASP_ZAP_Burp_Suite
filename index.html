Web 弱點掃描工具實務教學 (純網頁 Codespaces 版)

本平臺採用完全免安裝、純瀏覽器執行的 GitHub Codespaces 雲端架構，讓學生與測試人員能直接透過網頁體驗 OWASP ZAP 與 Juice Shop 的滲透測試實務。

1. 工具介紹與比較

在資安稽核中，中間人代理 (Proxy) 能攔截與動態修改 HTTP/HTTPS 封包。以下為兩種常見代理工具的特性比較：

比較項目 OWASP ZAP Burp Suite Community
授權費用 完全免費 / 開源 免費社區版 / 專業版需付費
網頁介面支援 (Web UI) 支援 (Webswing 容器) 需安裝桌面環境或獨立軟體

2. 核心原理與漏洞解析

中間人代理 (MitM Proxy)

代理伺服器位於用戶端與 Web 伺服器之間。所有發出的 HTTP 請求都會先經過 Proxy 監聽、暫停與修改後再發送至目標網站。

SQL 注入 (SQL Injection) 漏洞

當應用程式未過濾使用者輸入，直接拼接到資料庫查詢語句時，攻擊者可輸入如 ' OR 1=1 -- 來破壞原始 SQL 邏輯並繞過登入驗證。

3. Codespaces 純網頁實作建置指南

🚀 全純網頁模式：完全無須在個人電腦安裝 Docker、Burp Suite 或任何軟體！

快速啟動 3 步驟：

  1. 在 GitHub 專案頁面點擊 <> Code ➔ 切換至 Codespaces ➔ 點擊 Create codespace on main。
  2. 等待雲端 VS Code 載入完成後，在下方 Terminal (終端機) 複製貼上並執行以下指令： 
    docker run -d -p 3000:3000 --name juiceshop bkimminich/juice-shop && docker run -d -p 8080:8080 --name zap -i zaproxy/zap-stable zap-webswing.sh
  3. 切換至 VS Code 下方的 Ports 頁籤：
    • Port 3000：點擊右側網址開啟 Juice Shop 測試靶場。
    • Port 8080：點擊右側網址開啟 OWASP ZAP 網頁圖形化介面。

4. 雲端實作演練步驟

任務一：自動化弱點掃描 (使用 ZAP Web UI)

  1. 開啟 Port 8080 的分頁（ZAP Web UI 畫面）。
  2. 在主畫面的 URL to attack 欄位中，填入 Port 3000 的 Juice Shop 網址（如 http://localhost:3000）。
  3. 點擊 Attack 按鈕。
  4. 觀察 ZAP 自動執行爬蟲 (Spider) 與主動弱點掃描 (Active Scan)，並於下方的 Alerts 頁籤檢視發現的漏洞資訊。

任務二：SQL 注入驗證繞過

  1. 開啟 Juice Shop 靶場網頁（Port 3000），點擊右上角的 帳號 ➔ 登入。
  2. 在電子郵件欄位輸入萬能密碼：' OR 1=1 --
  3. 密碼欄位隨意輸入（如 123456），點擊登入。
  4. 驗證系統是否成功以最高管理員 (admin@juice-sh.op) 身分登入！

一、 測驗解答與詳細解析

第 1 題解答：選項 (2) 透過 Docker 啟動 Webswing 容器...

解析：OWASP ZAP 官方提供了含有 Webswing 的 Docker 映像檔，讓使用者無需安裝 X11 或桌面軟體，即可直接用瀏覽器開啟圖形介面。

第 2 題解答：選項 (2) SQL 注入攻擊...

解析：' OR 1=1 -- 利用單引號閉合語法、OR 1=1 恆真邏輯與 -- 註解符號，跳過密碼檢查取得權限。

二、 Juice Shop SQL 注入原理說明

伺服器接收到情境後執行的查詢語句如下：

SELECT * FROM Users WHERE email = '' OR 1=1 --' AND password = 'hash';

由於 1=1 恆為 True 且註解符號跳過了後續比對，資料庫直接回傳 User 資料表的第一筆紀錄（即 Admin 帳號）。
